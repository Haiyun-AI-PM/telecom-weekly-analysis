# 电信经营周报分析

## 何时使用

用户提供某一周期（或本期＋基线两期）的经营数据，要求产出周会可用的经营分析与下周行动建议，且数据是漏斗类数量指标（如线索、有效沟通、预约、办理/成交）。

不适用：需要联系客户、执行营销或人员调度的任务；单纯做图表美化；从业务系统实时取数；数据同步与清洗工程。

## 输入要求

必需三项，缺任意一项都要先说明会影响哪一部分结论：

1. **数据**：至少包含本期与对比基线（上期或同口径参照），字段为漏斗各级数量；有分期、分渠道、分产品维度更好。
2. **口径说明**：每个指标的定义、去重单位、时间窗、是否为同周队列、跨周跟进是否计入。
3. **业务资料**：场景与合规要求，当期已知业务动作（活动、资费变更、人员调整等）及其生效范围。

缺数据的处理：

- 只有一期数据 → 只做结构描述与环节间比较，不计算变化率。
- 没有指标定义 → 先请用户确认口径，不在默认假设下计算。
- 有数据但字段含义不清 → 列出待确认字段，只对已确认部分出结论。

## 执行步骤

1. **建输入清单**：数据来源、周期、字段、指标定义、业务资料要点；标注哪些是原始数据，哪些是他人口头反馈。
2. **数据合法性校验**（见下节），任一项不通过先报出来，再决定哪些指标可算。
3. **计算**各级比例与两种变化（百分点 / 相对变化），保留中间值以便复算。
4. **一句话结论**：先写变化事实，再写优先关注环节，不写原因判断。
5. **仅用户要求时做账面缺口分解**，并明确它是结构说明而非因果结论；默认不展示。
6. **切成三块**：确定事实、原因假设、待补数据。
7. **给不超过 3 项建议**，逐项写清角色、建议时限、验证方式、判为未落地的条件。
8. **按输出模板成文**，末尾过一遍自检清单。

## 校验清单

- 数量应为非负有限数值，计数应为整数；负数、非数值或逐级倒挂使相关指标不可计算，不静默取绝对值或填0。
- 基期为0时相对变化率未定义，写“无法计算相对变化”，可报告绝对增量；缺失值写待补，分母实际为0时标不适用。

- **逐级数量单调不增**：线索 ≥ 有效沟通 ≥ 预约 ≥ 办理（按实际定义顺序检查）。出现倒挂先问口径，不要强行解释。
- **零分母**：分母确实为0时该环节标“不适用”；分母缺失时标“待补”。两者均不得写0%。
- **缺失值**：区分"未采集"与"确实为零"；未采集写"待补"，不填 0。
- **期一致性**：两期时间窗长度、去重规则、统计范围一致；不一致标"不可直接比较"。
- **合计一致性**：分渠道／分产品之和与总数对不上时，列出差额并说明，不按差额调平。
- **精度**：比例保留 1–2 位小数，百分点差值同精度，四舍五入差异要说明。

## 计算与表述规范

- 环节转化率＝下一级数量／本级数量；整体转化率＝末级数量／首级数量。公式与中间值写进附录，便于他人复算。
- **变化必须双口径**：百分点变化（绝对差）与相对变化（差值／上期值）。两者可能结论相反，正文必须说明引用的是哪一个，不得笼统写"降幅更大"。
- **小基数提示**：小基数仅提示不确定性；没有统计检验或样本依据，不编造波动区间、显著性或因果结论。
- **缺口用数量表达**：给"若维持基线各环节转化率应有数量／实际数量／缺口"，比只讲比例更容易被业务接受。
- **账面分解必须声明顺序敏感**：逐环节替换时合计缺口不变，但各环节分摊随替换顺序变化。因此要①至少给两种顺序的分摊结果；②声明"只说明缺口落在哪一段，不能证明经营原因"；③避免"贡献""导致""主因"等因果措辞。

## 事实、假设与待补数据

- **确定事实**：只写数据直接支撑的内容（数量与比例的变化方向、幅度、是否同时发生）。不写原因、评价或预测。
- **原因假设**：每条标注来源与证据等级（结构化数据／非结构化反馈／经验判断）。非结构化反馈必须注明"未验证、未统计样本"，且不得出现在结论段。
- **待补数据**：按"要验证哪条假设、需要什么最小数据、由谁提供"列 3–5 项。
- **排序依据**：说明凭什么把某个环节排在前面（账面幅度、方向异常、基数稳定性），并声明它是待查线索而非原因结论。

## 行动建议要求

- 总数**不超过 3 项**；每项写全：动作、责任角色（岗位名，不写人名）、建议时限、验证方式（指标＋观察窗口＋回看方式）、判为未落地的条件。
- 涉及费用、资费、优惠的内容只给解释结构或待补字段，不编造金额、赠品或承诺。
- 涉及客户触达的建议必须写明授权与合规边界；无授权记录时不发消息。
- 目标值若不在输入数据中，标注为"待业务负责人确认的建议"，不作承诺指标。

## 默认交付形态

正文约600字，先给一句话结论、核心指标表和不超过3项行动建议。事实与原因假设明确区分；完整算式、校验清单和待补资料放附录，避免技术细节遮住业务结论。行动时限依据输入周期和实际计划执行日期写明，不能倒填已完成的动作或过去的计划。

## 输出模板

```
# 经营周分析（<周期>）
> 数据来源与口径／是否教学或演示数据／建议待确认声明

## 一、本周变化
<数量表：指标｜基线｜本期｜数量变化｜百分点变化｜相对变化>
数据校验：<结论；未通过项单独列出>
变化表述：<双口径说明，注明引用的是哪一种>
账面缺口分解：<仅用户明确要求时放入附录，标注顺序敏感与非因果>

## 二、优先关注环节
<1–3 段：排序、依据、为什么先查这一段；注明待查而非结论>

## 三、确定事实、原因假设与待补数据
确定事实：<仅数据支撑>
原因假设：<逐条标注来源与证据等级>
待补数据：<验证什么／需要什么／谁提供>

## 四、下周建议（≤3 项）
<表格：建议｜责任角色｜建议时限｜验证方法>
执行边界：<授权、合规、不承诺收益>
```

## 边界

- 只处理汇总数据，不采集或推断客户身份信息；不实际联系客户，不实施营销或人员调度。
- 教学、演示或模拟数据须在文首明确标注，避免被当作真实经营数据引用。
- 方法本身不内置任何一期数字、固定结论、客户或网格名称；每次分析都用当次输入重算。
- 只做分析与建议，不生成脚本、不依赖其他技能、不修改用户数据文件。
- 输出位置以用户指定为准；未指定时先问清路径再落盘。

## 自检清单

- [ ] 每个结论都能指回具体数量或公式？
- [ ] 百分点与相对变化都给了，且全文没有混用？
- [ ] 有没有把假设写成事实，或用"贡献／主因"暗示因果？
- [ ] 零分母、缺失值、逐级倒挂都已处理并说明？
- [ ] 建议 ≤3 项，每项都有角色／时限／验证方式／未落地判据？
- [ ] 授权与合规边界写清，费用信息未编造？
- [ ] 教学或演示数据已标注？
